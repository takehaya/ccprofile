# 実装計画

## 目的

任意の名前で Claude Code のアカウントと Anthropic Messages API 互換サービスを切り替える。既存の `~/.claude` を変更せず、子プロセスの `CLAUDE_CONFIG_DIR` と環境変数で分離する。

## 当初の計画

1. プロファイル検証、TOML、内部 ID、権限、ロックと原子的な更新。
2. 起動環境の分離、引数の配列での受け渡し、終了コードとシグナル。
3. macOS Keychain、公式ログイン、既存設定の明示的な登録。
4. doctor、偽の Claude Code によるテスト、README、CI。

## 最新の方針

利用者から Keychain を不要にし、ワンライナーで導入できるシェルスクリプトを優先したいとの変更があった。Keychain の実装は最終成果物から外した。ツールはトークンを保存せず、端末の非表示入力か環境変数で渡す方式を採用した。毎回の入力を省くため、利用者がシェルの起動設定で `CCPROFILE_TOKEN` を保持する手順も用意した。

シェル版では、`eval` や設定ファイルの `source` を使わず、値をデータとして読み込む。TOML・JSON・ロック・安全なファイル操作は、単体スクリプト内の Python 3.11 以降の標準ライブラリで扱う。`exec` で Claude Code に置き換えることで終了コードと Unix シグナルを引き継ぐ。インストーラーはユーザーの bin ディレクトリに配置し、シェルの起動設定を自動変更しない。

## 完成した実装

- 単体スクリプトの CRUD、公式 login、run、doctor。
- 権限・所有者・内部 ID・原子的な更新と排他制御。
- 設定の競合検出、環境変数の allowlist、引数の転送。
- トークンの非表示入力と環境変数入力。永続保存なし。
- ローカル／公開後の HTTPS インストーラー、README、仕様書、CI。

## 検証

- CRUD、必須項目、名前・URL の検証。
- 既存設定への明示的な接続、削除後も実データを保持。
- プロファイルごとの設定ディレクトリと起動環境。
- Bearer／API key、環境変数の除去、引数、モデル競合。
- 秘密情報を含まない表示とエラー。
- 同時更新、失敗時の既存設定保持、同時起動の分離。
- 終了コード、SIGINT、SIGTERM。
- オフラインのインストール確認。

実サービスへの接続と macOS 上の実 OAuth ログインは手動確認項目とする。

## OCR レビュー対応

初回レビュー（`.ocr/sessions/2026-10-15-main/rounds/round-1/final.md`）で確認した 6 件に対応した。

1. 専用プロファイルの `ANTHROPIC_CONFIG_DIR` も内部 ID 配下に分離する。
2. 既存 default の再利用では二つの設定先変数を未設定にし、標準の名前空間を維持する。
3. worktree の main checkout local settings を起動前検査と doctor に追加する。
4. 長いトークンを切り詰めない bounded noncanonical 入力と、属性・シグナルの復元を実装する。
5. 空のプロファイル表でも doctor が管理ルートの作成・書き込みを検査する。
6. URL の literal / encoded dot segment を拒否する。

HOME を含む祖先検査は、上流で実際の読み込みが確認されているため維持した。実装・回帰テスト・ドキュメントを更新し、30 件のオフラインテストが成功した。実 macOS の既存ログインと認証の分離は、実機未検証という制限を残す。詳細は [review-fixes.md](review-fixes.md) を参照する。
